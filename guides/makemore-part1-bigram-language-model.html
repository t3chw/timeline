What are we building?

1

The goal: make more names

▶ 0:00

makemore reads a file full of examples (here 32,033 first names) and learns to invent new ones that look like them.

  • It is a character-level language model. Each name is just a sequence of letters, and the model learns to predict the next letter.
  • This video builds the simplest version, a bigram model, and builds it two different ways that end at the same place.
  • Later videos widen it step by step: MLP, RNN, GRU, and finally a Transformer (about the size of GPT-2).
Remember
One score runs the whole video: the average negative log-likelihood, about 2.45 for the finished bigram model.
In one lineA bigram model predicts the next letter from the previous one, and we build it by counting and again with a neural net.

Take isabella. It is not one example, it is nine little facts about what follows what:

The bigram idea

▶ 5:39

A bigram model looks at only one letter, the previous one, and predicts the next:

  • What tends to follow r? What tends to follow a?
  • It ignores everything earlier in the name.

That makes it a very simple and weak model, but a great place to start.

In one lineBigram = predict the next letter using only the letter right before it.

Move the counts into a 2D tensor

▶ 12:45

A dictionary is awkward. A 2D array is easier: row = first letter, column = second letter, value = how often.

import torch
N = torch.zeros((28, 28), dtype=torch.int32)   # 26 letters + <S> + <E>

chars = sorted(list(set(''.join(words))))      # 'a'..'z'
stoi = {s: i for i, s in enumerate(chars)}     # char -> int
stoi['<S>'] = 26
stoi['<E>'] = 27
itos = {i: s for s, i in stoi.items()}         # int -> char (the reverse)

for w in words:
    chs = ['<S>'] + list(w) + ['<E>']
    for ch1, ch2 in zip(chs, chs[1:]):
        N[stoi[ch1], stoi[ch2]] += 1
  • Tensors default to float32. For counts we ask for integers with dtype=torch.int32.
  • Arrays are indexed with integers, so we need the char ↔ int lookup tables (stoi and itos).
In one lineN[row, col] += 1 fills a table of counts, using stoi to turn letters into row and column numbers.

One special token instead of two

▶ 20:54
  • The end token can never come first in a pair, so its whole row is zeros.
  • The start token can never come second, so its whole column is zeros.

Fix: use one special token, a dot ., and put it at index 0. Letters shift to 1 to 26, and the table becomes 27 × 27.

stoi = {s: i + 1 for i, s in enumerate(chars)}   # a=1 ... z=26
stoi['.'] = 0

Row 0 = how often each letter starts a name. Column 0 = how often each letter ends one. The pair ". ." never happens (no empty names).

In one lineUse a single '.' at index 0 for both start and end, giving a clean 27 x 27 table.

A row is a probability distribution

▶ 24:02

The table holds all we need to sample names. To pick a first letter, look at row 0:

Counts are not probabilities yet. Convert to float and divide by the row total so it sums to 1:

p = N[0].float()
p = p / p.sum()          # now sums to 1, shape (27,)

For example 'a' starts 4,410 of 32,033 names, so its probability is about 0.138.

In one lineDivide a row of counts by its sum and you get the probabilities of the next letter.

Drawing samples with torch.multinomial

▶ 26:28

torch.multinomial takes probabilities and returns integers drawn according to them. Seed a generator so everyone gets the same numbers:

g = torch.Generator().manual_seed(2147483647)
p = torch.rand(3, generator=g)
p = p / p.sum()                           # [0.6064, 0.3033, 0.0903]
torch.multinomial(p, num_samples=20, replacement=True, generator=g)
  • With p = 60% / 30% / 10%, about 60% of the draws are 0, 30% are 1, and only a few are 2. More draws means closer to those numbers.
  • Using the real first row, the first draw is index 13, which is m. That is a fair draw: m starts about 2,500 names, just under 10%.
Watch out

The sampling loop

▶ 31:32
ix = 0                                    # start at the '.' token
out = []
while True:

Precompute the probability matrix

▶ 36:17

Re-normalising a row inside the loop, every single step, is wasteful. Do it once for the whole table.

P = N.float()
P /= P.sum(1, keepdim=True)     # each row now sums to 1
  • P /= ... is in-place: no new tensor is created, so it can be faster.
  • He also wants the practice: building up to transformers needs comfort with n-dimensional tensors and broadcasting.

Careful though: the arguments 1 and keepdim=True matter a lot. Next three cards.

In one lineP holds a ready-made probability row for every letter, so sampling just reads P[ix].

sum() with dim and keepdim

▶ 37:55

P.sum() alone adds everything into one number. We want one total per row.

callresult shapewhat you get
P.sum()()one number, the grand total (wrong for us)
P.sum(0, keepdim=True)(1, 27)column totals, as a row vector
P.sum(1, keepdim=True)(27, 1)row totals, as a column vector (what we need)
P.sum(1)(27)same totals, but the size-1 dimension is squeezed away
  • dim says which dimension to add up along: 0 = down the rows, 1 = across the columns.
  • keepdim=True keeps that dimension as size 1 instead of deleting it.
In one lineUse sum(1, keepdim=True) to get a (27, 1) column of row totals.
16

Broadcasting rules

▶ 41:31

Can we divide a (27, 27) tensor by a (27, 1) tensor? That is decided by the broadcasting rules:

  1. Line the shapes up from the right.
  2. Going right to left, each pair of sizes must be equal, or one of them is 1, or one is missing.

Here the last sizes are 27 and 1 (one is 1, fine) and the first sizes are 27 and 27 (equal, fine). So it works: PyTorch stretches the size-1 dimension by copying it 27 times, then divides element by element. Every row ends up divided by its own total.

Check: P[0].sum() is 1.

His warning
Treat broadcasting with respect. Read the docs, practise it, and check your work, because it can create very subtle bugs.
In one lineShapes are lined up from the right; a size of 1 gets copied to match, so (27,27) / (27,1) divides each row by its own total.
17

The silent broadcasting bug

▶ 44:30

Drop keepdim=True and the totals have shape (27). Aligned from the right that looks like (1, 27), a row, which gets copied downwards. Now each column is divided by a total.

  • No error, no warning. The code runs and the numbers look plausible.
  • Test it: the first row no longer sums to 1. The first column does. So the columns were normalised, not the rows.
  • It stayed quiet because in this table the row totals happen to equal the column totals.
How to avoid it
Always keep keepdim=True here, and always check that P[0].sum() equals 1.
In one lineWithout keepdim the division runs in the wrong direction, silently, so always verify the row sums.

From likelihood to log-likelihood

▶ 53:02

In statistics the standard quality number is the likelihood: the product of all those probabilities, which equals the probability the model gives to the whole dataset. Higher is better.

  • Every factor is between 0 and 1, so the product becomes a tiny, unwieldy number.
  • So people use the log. It turns a product into a sum:
log(a · b · c) = log a + log b + log c

Probability 1 gives log 0. As the probability falls towards 0, the log falls towards minus infinity.

In one lineLog-likelihood is the sum of the logs of the probabilities, which is easy to accumulate and compare.

Negative log-likelihood is the loss

▶ 56:31
log_likelihood = 0.0
n = 0
for w in words:
    chs = ['.'] + list(w) + ['.']
    for ch1, ch2 in zip(chs, chs[1:]):
        prob = P[stoi[ch1], stoi[ch2]]
        log_likelihood += torch.log(prob)
        n += 1
nll = -log_likelihood
print(nll / n)          # about 2.45
  • The best log-likelihood is 0 (all probabilities 1) and it gets more negative when worse. But a loss should mean "low is good", so flip the sign: negative log-likelihood (NLL).
  • NLL is 0 at best and bigger when the predictions are worse.
  • Divide by the number of pairs to get the average NLL, a friendlier number.
datatotal NLLaverage
first 3 names38.79
all 32,033 names559,891.752.454
In one lineAverage negative log-likelihood is the loss: 0 is perfect, lower is better, and our bigram scores about 2.45.

The goal in four equivalent lines

▶ 58:35

He writes the goal as a chain of statements that all mean the same thing:

  1. Maximise the likelihood of the data with respect to the model's parameters.
  2. = maximise the log-likelihood (log never changes which option is best, it just rescales).
  3. = minimise the negative log-likelihood.
  4. = minimise the average negative log-likelihood.

The model's parameters here are simply the numbers in the table P. In Part 2 they will come from a neural network instead.

In one lineMaximising likelihood, maximising log-likelihood and minimising average NLL are the same job.

Model smoothing with fake counts

▶ 1:01:29

Fix: pretend we saw every pair a few extra times.

P = (N + 1).float()             # add one fake count to every cell

Same task, neural-net style

▶ 1:03:51

The counting model works, but we reached it by doing something that "felt sensible". Now we re-cast the problem the way neural nets do it:

  • The net gets one character as input and has weights W.
  • It outputs a probability distribution over the next character.
  • We know the true next character (the label), so we can read off how much probability the net gave it. High probability = low loss.
  • Then we use gradient-based optimisation to tune W so the loss goes down.

Same bigram model, same loss, a very different route.

In one lineA neural net outputs next-letter probabilities from W, and we tune W to lower the same NLL loss.

One-hot encoding

▶ 1:10:41

We cannot feed the integer 13 into a neuron: neurons multiply inputs by weights, and "13" is a label, not a quantity. Instead use a one-hot vector: all zeros, with a single 1 at the integer's position.

import torch.nn.functional as F
xenc = F.one_hot(xs, num_classes=27).float()
xenc.shape          # (5, 27)
  • Each row is one example, with exactly one cell switched on (columns 0, 5, 13, 13 and 1 for "emma").
  • Pass num_classes=27 so it does not guess a smaller size.
  • one_hot returns int64 and cannot be asked for floats, so cast with .float(). Neural nets want floats.
In one lineOne-hot turns a letter number into a 27-long vector with a single 1, ready for a neuron.

One neuron, then 27 neurons

▶ 1:13:37

A neuron computes w · x (no bias here). Weights start as random numbers from a normal distribution: mostly near 0, rarely beyond ±3.

W = torch.randn((27, 1))
xenc @ W            # (5,27) @ (27,1) -> (5,1)   one number per example

@ is matrix multiplication: all 5 examples run through the neuron in parallel. Now use 27 neurons instead of 1:

W = torch.randn((27, 27))
xenc @ W            # (5,27) @ (27,27) -> (5,27)
  • Entry [3, 13] = how strongly neuron 13 fires on example 3 = the dot product of row 3 of xenc with column 13 of W.
  • It is a single linear layer: no bias, no tanh, no other layers. "The dumbest, smallest, simplest neural net."
In one linexenc @ W runs every example through all 27 neurons at once, giving a (5, 27) table of outputs.
28

The outputs are logits (log-counts)

▶ 1:19:16

We want probabilities, which must be positive and sum to 1. The raw outputs are positive and negative, so that does not work directly. And they cannot be counts, which are positive integers.

The trick: read the outputs as log-counts, also called logits. Then undo the log with exp:

logits = xenc @ W          # interpreted as log-counts
counts = logits.exp()      # now positive "counts", like the N table
  • A negative logit becomes a number between 0 and 1.
  • A positive logit becomes a number above 1, growing quickly.
  • So counts are always positive, just like the counting table N.
In one lineTreat the layer's outputs as log-counts, and exp() turns them into positive pseudo-counts.

Softmax

▶ 1:23:21

Counts to probabilities is what we did before: divide each row by its total.

probs = counts / counts.sum(1, keepdims=True)    # each row sums to 1

These two steps, exp then normalise, have a name: softmax.

pi = eziΣj ezj
  • It takes any real numbers and outputs positive numbers that sum to 1.
  • You can put it on top of any layer to make a network output a probability distribution.
  • Every step so far (multiply, add, exp, sum, divide) is differentiable, so we can back-propagate through all of it.
In one lineSoftmax = exp, then divide by the row total, and it is differentiable end to end.

The full forward pass

▶ 1:26:13

Guess-and-check vs gradients

▶ 1:31:32

He tries re-rolling W with a different seed: the loss becomes 3.37, then worse values for other seeds. Randomly assigning parameters and checking is, in his words, "amateur hour".

The right way: start from one random W and commit to it. The loss is built only from differentiable steps, so we can compute the gradient of the loss with respect to W and nudge W downhill.

  • It is the same recipe as micrograd: forward pass, backward pass, update. He shows the old micrograd notebook next to the new one.
  • Two differences: the net is just one linear layer plus softmax, and the loss is negative log-likelihood (for classification) instead of mean squared error (for regression).
In one lineDon't re-roll weights randomly; follow the gradient of the loss to improve W.

The loss in one line

▶ 1:35:59

The backward pass

▶ 1:38:26
W = torch.randn((27, 27), generator=g, requires_grad=True)   # track gradients for W

W.grad = None            # reset (None works like zero, and is more efficient)
loss.backward()          # fills W.grad
W.grad.shape             # (27, 27), same as W
  • requires_grad=True tells PyTorch to record how W was used. It is off by default.
  • While the forward pass runs, PyTorch quietly builds a computational graph, like in micrograd. backward() walks it in reverse.
  • Each entry of W.grad says how much that weight influences the loss. A positive gradient means increasing that weight would raise the loss.
  • For "emma" most rows of W.grad are zeros: only the rows of letters that appeared as input receive gradient.
In one lineloss.backward() fills W.grad with how each weight affects the loss.

The update step

▶ 1:41:15

Move every weight a little in the opposite direction of its gradient:

W.data += -0.1 * W.grad

Re-run the forward pass and the loss is lower: 3.769 → 3.749 → 3.729 and so on, each round a bit better.

No loop over parameters is needed because there is only one parameter tensor, W.

In one lineForward, reset, backward, update: repeat, and the loss keeps dropping.

    counts = logits.exp()
    probs  = counts / counts.sum(1, keepdims=True)
    loss   = -probs[torch.arange(num), ys].log().mean()
    W.grad = None
    loss.backward()
    W.data += -50 * W.grad
  • Change nothing but the data: now 228,146 examples. The code "doesn't care" whether there are 5 or 228,146.
  • Learning rate: 0.1 crawls (3.76 to only 3.75 after 10 steps on the full data). 50 works: 3.76 → 2.69 in 10 steps. That is huge, but this problem is very simple.
  • After a few hundred steps the loss settles around 2.46.
In one lineRun the same loop on all 228,146 pairs with a big learning rate and the loss falls to about 2.46.

Why use the neural net at all?

▶ 1:45:39

If counting works, why bother? Because the gradient route is far more flexible:

  • Soon we feed in several previous letters and use deeper networks.
  • A table cannot follow: with k letters of context it needs 27k rows. With 10 letters that is roughly 2 x 1014 rows (my arithmetic), so counting is unscalable.
  • Whatever network we build, the output is always logits, then softmax, then NLL loss, then gradient descent.
The big promise
Going all the way up to transformers, none of this changes. Only the forward pass (how logits are computed from earlier characters) gets more complex.
In one lineThe neural-net recipe stays the same as the model grows; only the forward pass changes.

Insight 1: one-hot @ W is a row lookup

▶ 1:47:27

Multiplying a one-hot vector by W plucks out one row of W. So the logits for letter 5 are literally row 5 of W.

That is exactly what the counting model did: the first letter indexed a row of the table. So:

  • W holds log-counts, so W.exp() plays the role of the count table N.
  • Counting fills the table in directly. The net starts it random and arrives at (about) the same table by following the loss, piece by piece.
In one lineW is the log of the counts table: one-hot times W just looks up a row.

Insight 2: smoothing is regularization

▶ 1:50:31

Remember smoothing: more fake counts made rows more uniform. The neural net has an equivalent.

  • If W = 0, then logits are all 0, exp gives all 1s, and the probabilities are exactly uniform.
  • So encouraging W to stay near zero smooths the model, just like fake counts do.
  • Doing that by adding a term to the loss is called regularization.
In one linePushing W towards 0 makes predictions more uniform, which is the neural-net version of smoothing.

The regularization loss in code

▶ 1:51:58
loss = -probs[torch.arange(num), ys].log().mean() + 0.01 * (W**2).mean()
  • W**2 squares every weight, so signs vanish. It is 0 if W is all zeros and grows as weights get large.
  • Use mean rather than sum so it stays a manageable size (at the start the sum was about 1,539, the mean about 2.11).
  • The loss now has two parts: match the data, and keep W small. He calls the second one a spring or a gravity pulling W to zero.
  • The strength (0.01 here) acts like the number of fake counts. Make it huge and predictions become fully uniform.
  • With it, the full-data loss ends near 2.48, a touch above 2.46 because the spring costs a little fit.
Link to your other notes
This is what is usually called L2 regularization. In the MAP view it is a Gaussian prior on the weights.
In one lineloss = NLL + 0.01 * mean(W**2): the penalty pulls weights to zero, like smoothing.

Part 2 test: can you explain it?

▶ 1:57:00

Try to answer out loud first, then open each one.

Why can't we feed the integer 13 straight into a neuron, and what do we do?
A neuron multiplies inputs by weights, and an index is a label, not a quantity. Use a one-hot vector (27 numbers, a single 1), cast to float.
What shape is xenc @ W for 5 examples and a 27 x 27 W, and what does entry [3, 13] mean?
Shape (5, 27). Entry [3, 13] is neuron 13's output for example 3: the dot product of row 3 of xenc with column 13 of W.
What are logits and how do they become probabilities?
Logits are the raw outputs, read as log-counts. Take exp to get positive counts, then divide each row by its sum. That pair is the softmax.
How do you get the probability of the correct next letter for every example in one line?
probs[torch.arange(n), ys]. Then .log().mean() with a minus sign gives the loss.
What are the four steps of one gradient-descent iteration?
Forward pass to the loss; reset W.grad = None; loss.backward(); update W.data += -lr * W.grad.
Why does the neural net end at about the same loss as counting?
Both use the same information (the previous letter) and the same model family. Gradient descent finds the table counting computes directly.
What does one_hot(x) @ W do, and what does W.exp() resemble?
It selects row x of W (a lookup). W holds log-counts, so W.exp() resembles the count table N.
How is regularization related to smoothing?
W = 0 gives uniform probabilities, so pulling W towards 0 (the penalty term) smooths the model, like adding fake counts. A stronger penalty means more fake counts.
Why is the table approach unscalable, but the neural net is not?
With k letters of context a table needs 27^k rows. A neural net computes logits from the input instead, so only the forward pass grows.

Gotchas he points out

▶ 44:30
  1. sum() needs dim and keepdim. Otherwise it sums everything or squeezes a dimension.
  2. Broadcasting can silently go wrong. Without keepdim the wrong direction is normalised. Check P[0].sum().
  3. multinomial needs replacement=True to draw several samples.
  4. torch.Tensor vs torch.tensor: capital gives floats, lowercase keeps integers. Prefer lowercase.
  5. one_hot returns integers. Cast with .float().
  6. A zero probability gives infinite loss. Smooth the model.
  7. Set W.grad = None before each backward pass, or gradients pile up.
  8. requires_grad=True on W, or backward has nothing to fill.
  9. Don't guess-and-check weights. Use the gradient.
  10. Learning rate depends on the problem. 50 works for this tiny one, not in general.
